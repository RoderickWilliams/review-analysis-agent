# 需求逐项确认

## 工作方式
- 用户要求：一次提问，回答后更新需求与实现；问清后统一检测。
- 本轮旧快照检查结果：150 项离线测试通过，88 Python / 7 JS 语法通过，wheel 构建与资源检查通过；额外复现 10 项边界问题，不能宣称全功能正常。
- 当前预览为假模型隔离实例，不代表真实模型或平台采集已经验收。

## 已确认
1. 最终验收范围为完整业务链路：自动找同款、京东/淘宝/天猫/小红书真实采集、模型分析、洞察、运营方案、导出和历史管理。
2. 使用用户提供的 ReviewAgent 图片作为 Logo，保留原图设计。
3. 分析历史需要“清除记录”按钮；实现时阻止清除运行中的任务，并提供撤销入口。
4. 严格归并：只有同品牌、同型号、同关键规格才能合并评论；不同规格和竞品分别建组、并列比较。规格无法确认时标为待确认，不自动混入。
5. 默认标准档：每个平台、每个商品最多 300 条，优先最近 12 个月；不足时补更早样本并单独标注。未采足时显示实际数量与缺口，不补造评论。
6. 用户角色是运营人员，要求通用支持所有品类，不以老板或店主为默认角色。自动识别品类与关键规格；不强制要求成本、毛利、供应链数据。运营建议区分“可直接执行”和“需负责人确认”，未知数据不编造。
7. 运营输出包括诊断、优先级行动、验证指标，并附可编辑的商品卖点、客服话术、内容选题与排期草稿。每项保留证据、推导说明和待确认项，可在工作台修改后导出。
8. 沿用用户本机已有的 DeepSeek API 配置，不在对话中收集或显示 Key。一次完整分析的模型费用目标低于 1 元，允许最多额外 0.5 元，总上限 1.5 元；所有阶段及重试共用预算。全部评论先进行本地去重和统计，模型在预算内分批处理并优先代表样本，超出上限的部分沿用该策略，明确显示模型实际覆盖范围，不能把抽样结论写成全量逐条模型分析。需要预估、调用前预算预留、实际 usage 记账和安全余量；目前尚未实现或真实验收费用控制。
9. 应用主面板采用固定尺寸的圆角矩形，内容增长不撑高外框；长内容在框内右侧通过可拖动的竖直滚动条浏览。当前实施值为桌面 1440 × 900px、圆角 14px，窗口不足时缩小到可用空间；顶部工具栏固定，弹窗与证据面板也在内部滚动。
10. 采集需登录时，打开用户默认浏览器的登录页，由用户扫码；确认会话有效后自动继续并关闭本次登录窗口，保留其他平台进度。登录状态只在本机持久复用，过期或撤销后重新登录，不承诺永久有效。降低平台限制触发的方案为限速、退避、断点续采、减少重复请求；遇到验证码或访问限制暂停并由用户完成，不承诺避免封控或绕过验证。
11. 用户接受默认浏览器程序的 ReviewAgent 专用窗口与独立持久配置，不直接使用日常账号配置。当前支持方案为本机 Chrome、Edge、Firefox 的系统默认关联；无法连接时明确报错，不接管或关闭日常窗口。
12. 首次统一真实验收以 Folkmanis 为品牌入口，自动寻找能核对型号和规格的具体商品，生成一份完整报告，模型总费用不超过 1.5 元。不同型号分组；不能把整个品牌当作同一商品。官方 Mini Fox 页面可提供型号 2644 的核对参考：https://www.folkmanis.com/prod-275-1-121-14/mini-fox.htm 。这不是京东/淘宝/天猫/小红书评论已经采到的证据。
