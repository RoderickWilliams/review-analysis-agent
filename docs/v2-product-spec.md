# ReviewAgent v2 产品规格（已确认需求）

状态：对象层已实现（京东链接解析、同 SPU 匹配、对象层报告、本地工作台）；跨平台评论采集、自动找同款与运营方案生成待接入

目标仓库：https://github.com/RoderickWilliams/review-analysis-agent
分支：v2（确认演示与报告后再合并 main）

## 0. 一句话

以商品链接、商品名或小红书笔记为起点，跨淘宝/天猫、京东、小红书采集公开评论与笔记，产出口碑诊断、用户痛点、产品改进方向、内容选题与内容生产包，并给出可执行的运营方案与行动清单。每条事实可回查，每条建议都标明依据。

## 1. 范围

第一版平台：淘宝/天猫（同一平台）、京东、小红书。抖音、拼多多、快手、微博后续加，不改报告骨架，只加采集适配器和平台标签。

同款范围：同款 + 近似款。同型号、同系列、同规格允许不同颜色、容量、套装。竞品只在用户明确要求时单独成节，不混入本品主评分。

只读边界：不发布、不点赞、不评论、不关注、不私信。不把破解验证码、绕过登录或封禁、规避平台访问控制作为交付目标。

## 2. 入口与对象识别

单输入框接受：淘宝/天猫商品链接、京东商品链接、小红书笔记或商品链接、商品名。

提交后显示「分析对象」卡片：对象类型、平台、标题、对象 ID、链接、归属（自家/竞品，默认自家）、识别置信度、来源。类型识别错误时允许手动改类型、改归属、删掉错误链接。

置信度规则：

- 直接商品链接：不打断，直接进入采集。
- 商品名或笔记链接：置信度高直接跑；置信度低先给 2–3 个候选，允许手动输入商品名或商品链接。
- 小红书笔记识别不出商品：给 2–3 个候选商品 + 手动输入窗口。选候选则跨平台分析；不选则只分析该笔记正文、图片文字和评论，报告标注「未做跨平台同款采集」。

同一任务允许补充多个商品链接作为同款/近似款样本。用户补充的链接排在自动发现结果之前，但经过同一套去重和匹配度标注。

## 3. 采集

### 3.1 档位

下拉栏四档，默认标准。生成后可调升/调降，增量重跑，不重做已采部分。

| 档位 | 商品或商家 | 每商品评论 | 小红书笔记 | 说明 |
|---|---|---|---|---|
| 轻量 | 3（建议值，待确认） | 50（建议值） | 10（建议值） | 快速看方向 |
| 标准 | 5 | 100 | 20 | 默认，主样本 |
| 深度 | 10（建议值） | 200（建议值） | 50（建议值） | 覆盖更全，耗时更长 |
| 自定义 | 用户上限 | 用户上限 | 用户上限 | 单项最高值由程序限制并提示 |

报告写清实际档位、各平台采集量、失败项与缺口。标准档数值已确认；轻量/深度默认值待最终确认。

### 3.2 时间

默认最近 12 个月，从新到旧取。不足 30 条自动向前补。报告写清补了多少、最老一条时间、各平台缺口。用户可在分析对象卡片改时间范围。

### 3.3 登录与 cookie

默认匿名采集。需要登录时先提示平台和原因；用户同意后打开默认浏览器窗口，由配套扩展在登录完成后回传 cookie 到本机服务，固化登录态供后续复用。cookie 只存本机，不上传，不写进报告、日志或插件返回值。失败时回退为重新登录、换浏览器、手动导入 cookie，不假装成功。

### 3.4 稳定性

节流、重试、缓存、平台限速、选择器自愈。平台改版导致解析失败时，报告标记该平台采集失败，不拿旧数据冒充新数据。

## 4. 同款匹配与取样

匹配依据按优先级：品牌 + 型号/系列 + 规格；标题关键词与属性字段；价格带（只用于去重）；销量/评价量（只用于排序）。

排序：匹配度优先，其次销量，再做价格带去重。默认只分析 5 个。

每个候选带：匹配等级（同款/近似款/竞品/不确定）、匹配理由、价格、销量、评论数、链接。用户可移除或补充。

竞品模式：分析对象卡片选「竞品」后，报告增加「对标与差异化」，运营方案改写为对标动作，不写「改我的详情页」。

## 5. 分析流水线

1. 归一化：商品、笔记、评论统一为带 source_url、platform、captured_at 的记录。
2. 情绪与有效性：沿用现有 9 类情绪、8 类有效性、交叉验证。
3. Trust Report：突发、重复、评分矛盾、后验区间、风险等级。
4. 痛点：结构化 LLM 抽取 + 引语校验。引语必须能在原文或图片文字里找到，找不到标 unverified，不进榜单。
5. 改进方向：P0/P1/P2，每条引用 pain_point_id，给成本、影响、验证方式。
6. 选题与内容包：人群、痛点、标题、封面、正文骨架、标签、风险词；内容包给主图 brief、详情页 8 段、15 秒 5 分镜、英文清单、素材索引，不生成图片。
7. 运营方案：按需生成，商品页转化、定价促销、内容流量三组动作，最后给本周行动清单。
8. 行动清单：独立 CSV / Markdown，字段含优先级、动作、依据、验证指标、负责人、截止时间（可空）。

## 6. 运营方案

自家商品：

A. 商品页转化：标题改写方向、卖点排序、主图方向（1:1 / 3:4 / 16:9）、详情页 8 段、FAQ、客服话术。
B. 定价促销：价格带判断、套装/规格组合、优惠券与活动节奏、赠品建议。
C. 内容流量：搜索关键词、小红书选题、达人合作方向、投放素材方向。

最后给「本周先做什么、为什么、怎么验证」的行动清单。证据支持的动作和需要商家确认的动作分开写。

竞品：输出对标与差异化，指出对方占优的卖点/价格带/内容角度、我方可以打哪里、不建议照搬什么。不写只有店铺后台才能执行的改价、改库存动作。

经营数据：默认只用公开数据。可选手填转化率、客单价、投放花费、退货率；可上传 CSV/Excel 做列映射；不接店铺后台/API。报告标数据来源（公开采集/商家手填/上传表格），商家数据标「未经平台核验」。

## 7. 报告结构与界面映射

报告章节：总览；口碑诊断（情绪、有效性、Trust）；痛点图谱；竞品对照（可选）；增长机会（改进、选题、内容包）；运营方案；证据与方法（采集量、缺口、引语校验、模型与规则版本）。

界面一级标签：总览（总览、证据摘要）；口碑诊断（口碑诊断、痛点图谱、竞品对照）；增长机会（改进方向、选题、内容包）；运营方案（运营方案、行动清单）。

所有端首屏仪表盘：口碑总分、样本量、风险等级、痛点数量、机会数量、采集覆盖。图表不只靠颜色区分，配文字标签和可展开数据表。每条痛点、改进、选题带证据链接，能回到原帖或原评论。

## 8. 数据真实性规则

禁止生成任何虚假内容。四层：

1. 事实层：原句、评分、时间、链接、数量必须来自采集。引用可回查。查不到就删掉或标「未验证」。
2. 统计层：占比、频次、信任分由程序计算，不让模型随口给。
3. 建议层：运营动作、改进、选题可以生成，标「建议」并附依据。没有依据就写「样本不足」。
4. 文案层：标题、封面、卖点草稿标「建议/草稿」，不冒充真实用户原话，不编参数、认证、销量、效果承诺。

数字规则：真实采集统计照实展示；模型生成的草稿、目标、承诺里的数字不写实数，用 `x` / `xx` 占位；演示版所有数字用 `x` / `xx`，区块标「演示数据 / AI 生成样例」，示例评论标「示例用户」。

## 9. Web UI 设计

方向：面向商家、运营、品牌方的电商口碑分析工作台。默认浅色专业数据台，保留深色切换。证据优先，长报告可读。不做营销落地页，不做花哨动效。

桌面 ≥1200px：左侧固定目录（章节 + 阅读进度，可折叠）；右侧内容区顶部一级标签（总览 / 口碑诊断 / 增长机会 / 运营方案）；每个标签页顶部先给仪表盘卡片，再往下是正文和证据；点卡片跳到对应章节。报告不拆成七个孤立页面，章节仍在同一内容区滚动，目录负责定位。

平板 768–1199px：左侧目录收起，变顶部标签 + 下拉目录；仪表盘卡片两列。

移动 <768px：单列长页，顶部吸顶分段标签，目录收进「章节」按钮；仪表盘卡片横向滑动或单列堆叠，先看结论，再读证据。

主题三选一：跟随系统 / 浅色 / 深色。焦点经过不预览，确认才生效。持久化到 localStorage。深色用独立语义令牌，不反转浅色。正文对比度 ≥ 4.5:1，大字与控件 ≥ 3:1。键盘可达，焦点可见，图表有文字替代，表格可横向滚动。打印/导出强制浅色，展开折叠内容，隐藏导航。

视觉令牌：浅色用冷灰背景、白色卡片、蓝色主操作、绿色低风险、琥珀中风险、红色高风险；深色用深蓝灰背景、分层卡片、同一语义色提亮。字体用系统无衬线，中文优先 Microsoft YaHei / PingFang SC。卡片圆角 14px，控件 10px，阴影轻，不用大面积渐变。

技术形态：本地 Web 单页由 FastAPI 同进程提供，静态资源随包分发，不依赖 CDN。默认 `reviewagent serve` 打开 `/app/`。Streamlit 旧界面保留代码，不再作为部署目标。

## 10. 三形态与部署

保留四种入口：CLI、HTTP API、DSH 插件、Agent Skill。

本地完整版：用户自己的机器直接跑完整服务，不受演示限制。

云端：用户主动选「部署到云端」才走。一条脚本完成装 Docker、拉仓库、生成配置、起服务、自动 HTTPS；服务器、公网 IP、端口、域名/备案由用户准备。脚本给详细提示，不默认执行。

演示版：托管 Cloudflare Pages 为主，GitHub Pages 做镜像，EdgeOne Pages 作为国内备选；上线前实测首屏，不承诺国内一定快。演示输入框可用，提交后返回预置样例报告，所有内容标「演示数据/AI 生成样例」。首次打开弹可关闭的能力介绍悬浮窗，关掉后不再自动出现，留「关于」入口。

Star 校验：安装时用 GitHub Device Flow 校验账号是否 star 仓库，通过后生成本地激活令牌再部署。公开代码仍可被改后绕过，说明里写清。

安全：API 没有鉴权时只绑 127.0.0.1；云端必须加鉴权与 TLS；密钥只走环境变量；cookie 只存本机。

## 12. API 草案

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /v1/object/resolve | 识别链接/商品名，返回候选 |
| POST | /v1/analysis | 创建分析任务（对象、档位、时间、归属） |
| GET | /v1/analysis/{id} | 任务状态与进度 |
| GET | /v1/analysis/{id}/report | 报告 JSON |
| GET | /v1/analysis/{id}/report.html | 单文件报告 |
| GET | /v1/analysis/{id}/actions.csv | 行动清单 |
| POST | /v1/analysis/{id}/ops-plan | 按需生成运营方案 |
| GET | /v1/analysis/{id}/evidence/{ref} | 证据详情 |

实现以现有 /v1/* 为基础扩展，不破坏已有接口。

## 13. 验收标准

1. 输入 10 篇小红书笔记及评论，产出综合报告 + 行动清单；每条痛点、改进、选题能点回原文。
2. 输入淘宝/京东商品链接，能发现同款/近似款并跨平台采集；找不到时给关键词和候选，允许人工补链接。
3. 输入商品名，能返回候选商品并完成跨平台分析。
4. 伪造或改写过的引语被校验拒绝，不出现在榜单。
5. 档位切换后增量重跑，不重复采集已完成部分。
6. 演示版所有数字是 x/xx，所有区块标演示来源。
7. 桌面/平板/移动布局符合第 9 节，浅色/深色/打印均可用，正文对比度达标。
8. 现有 123 项测试不回归；新增解析、采集、洞察、UI 接口测试通过。
